PART 2 - THE PROJECT (what to build)
----------------------------------------------------------------

ONE-LINE CONCEPT
Run a process-mining analysis on a real public service-ticket log,
framed as an analog for appliance after-sales service, and surface
where tickets bounce, stall, and reopen.

TOOLS (all free, all Python)
- PM4Py - free Python process-mining library. Sits on top of
  Pandas, which is already known. No Celonis license needed.
- Pandas, matplotlib for KPIs and charts.
- Jupyter notebook for the narrated analysis.
- GitHub for hosting the final artifact + README.

DATASET - pick ONE real public event log
- BPI Challenge 2013 (Volvo IT incident management) -- PREFERRED.
  Incidents with reassignments and reopens. Famous for the
  "ping-pong" problem (tickets bouncing between teams), a perfect
  analog for repeat technician visits.
- Helpdesk log (Italian software company) -- easier/smaller fallback
  if the above is fiddly to load.

HONESTY FRAMING (state this in the README)
"I used a public IT-service-desk log as a stand-in for an appliance
after-sales process - the event structure (ticket lifecycle,
reassignments, reopens, SLA) is identical." This shows understanding
of process transfer; it is a strength, not an excuse.


----------------------------------------------------------------
PART 3 - THE ANALYSIS (5 questions = the real work)
----------------------------------------------------------------
These map 1:1 to service-operations KPIs. Answering them is what
makes this look like analyst work, not a copied tutorial.

1. HAPPY-PATH CONFORMANCE
   Discover the real process map vs the ideal one. What % of tickets
   follow the clean path vs take a detour?

2. FIRST-TIME-FIX / REOPEN RATE
   What fraction of tickets get reopened or re-worked? (The #1 hidden
   cost in field service.)

3. BIGGEST REWORK LOOP
   Find the ping-pong: which reassignment loop wastes the most time?

4. THE BOTTLENECK
   Which step has the longest WAITING time (e.g. wait-for-parts,
   wait-for-assignment)?

5. ONE DRIVER (diagnostic)
   Does the number of reassignments predict resolution time? A simple
   correlation/regression. Same style as the existing churn/NPS work
   - find the threshold and the cause, with numbers.
